    *   **Статус:** ВЫПОЛНЕНО. Проект уже использует файл `.env.backend` для хранения приватного ключа и других секретов.

## 📈 Приоритет 2: Функциональное развитие

*   [x] **Поддержка новых блокчейнов (Bitcoin, Ethereum).**
    *   **Проблема:** Текущая архитектура жестко привязана к сети TRC-20.
    *   **Решение:** Создать базовый класс-интерфейс для работы с блокчейном (`BlockchainService`) и реализовать от него классы-наследники для каждой сети (`TronService`, `BitcoinService`, `EthereumService`). Это позволит легко добавлять новые сети в будущем.
    *   **Прогресс:**
        *   [x] Создан базовый класс `BaseBlockchainService`.
        *   [x] Существующая логика для Tron вынесена в `TronService`.
        *   [x] Реализована полноценная отправка транзакций для `BitcoinService` с использованием `btclib` и `mempool.space`.
        *   [x] Реализована "фабрика" для получения нужного сервиса.
        *   [x] Фоновые задачи (`tasks.py`) обновлены для работы с фабрикой и мультисетевыми системными кошельками.

*   [x] **Реализовать полноценный процесс вывода средств.**
    *   **Проблема:** Логика вывода средств была не до конца интегрирована с подтверждениями по email и 2FA.
    *   **Решение:** Добавить шаги подтверждения вывода в `Withdrawal` модели и сервисах.
    *   **Прогресс:**
        *   [x] Реализован полноценный процесс подтверждения вывода по email.
        *   [x] Логика вывода вынесена из сериализатора в `WithdrawalService`.
        *   [x] Добавлен новый API-эндпоинт для обработки токена подтверждения.
        *   [x] На фронтенде (Next.js) создана страница для обработки подтверждения.
        *   [ ] Осталось добавить опциональное подтверждение через 2FA.

*   [x] **Универсальная система депозитов (без memo).**
    *   **Проблема:** Текущая система пополнения счетов работала только для валют, поддерживающих `memo`/`Destination Tag`.
    *   **Решение:** Реализована система генерации уникальных депозитных адресов для каждого пользователя для валют без `memo` (например, Bitcoin).
    *   **Прогресс:**
        *   [x] В модель `UserWallet` добавлено поле `deposit_address` для хранения уникального адреса.
        *   [x] В `BitcoinService` добавлена логика генерации новых адресов из системного HD-кошелька (xpub).
        *   [x] `DepositService` теперь генерирует и сохраняет уникальный адрес для пользователя при первом запросе.
        *   [x] Фоновая задача `check_blockchain_deposits` корректно сканирует транзакции по этим уникальным адресам.
        *   [x] Создан API-эндпоинт `GET /api/crypto/deposit/info/` для получения адреса фронтендом.
        *   [x] На фронтенде в `DepositForm` реализована загрузка списка валют и получение адреса для пополнения с отображением QR-кода.

## 🛠️ Приоритет 3: Рефакторинг и оптимизация

*   [ ] **Рефакторинг API в `views.py`.**
    *   **Проблема:** Дублирование логики в функциях получения курсов и выполнения обмена.
    *   **Решение:** Объединить похожие функции в единые сервисные методы, чтобы избежать повторения кода.

*   [ ] **Оптимизация запросов к базе данных.**
    *   **Проблема:** В некоторых местах (например, при получении цен) можно уменьшить количество запросов к БД с помощью `select_related` и `prefetch_related`.
    *   **Решение:** Проанализировать запросы с помощью Django Debug Toolbar и оптимизировать их.
